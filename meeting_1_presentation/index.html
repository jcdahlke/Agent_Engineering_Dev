Agent Frameworks

One Pipeline, Six Frameworks

Used Claude Code to build the same multi-agent research pipeline in six different SDKs so students can read the same problem expressed six ways and compare the primitives.

🎯 → 🔍 → 📊 → ✍️ → 🧐

Supervisor → Researcher → Analyzer → Writer → Critic

Critic loops back to Writer until quality threshold is met or max_iterations is hit. The behavior is identical across frameworks; the APIs, state model, and orchestration patterns are deliberately different.

📦

Same problem

Identical pipeline shape, identical role names, identical end output.

🔧

Different primitives

State carriers, edge wiring, and HITL look completely different in each framework.

📚

Side-by-side reading

Each subdir is self-contained — students can diff one framework against another to see the trade-offs.

Direct Comparison

OpenAI Agents SDK vs client.responses

Same task, two abstraction levels. The SDK trades hand-rolled control for batteries-included orchestration.

In-class pattern: client.responses

  • Raw client.responses.create() in a manual loop
  • You inspect response.output and dispatch tool calls yourself
  • Conversation history threaded by hand (previous_response_id or list of items)
  • Multi-agent routing = your own if/elif over outputs
  • Streaming = iterate raw event chunks
  • You own retries, errors, guardrails, and tracing

Agents SDK: Agent + Runner

  • Agent(name, instructions, tools, handoffs) declarative spec
  • Runner.run(agent, input) handles the loop
  • Handoffs / agent.clone() wire multi-agent routing
  • Sessions: AsyncSQLiteSession, OpenAIConversationsSession, previous_response_id
  • Runner.run_streamed + typed events out of the box
  • Built-in guardrails, hooks, tracing, structured output

References: OpenAI_Agents_Comparison.ipynb · agents_chat_demo.py (Gradio demo of all four session strategies)

Kaggle

Orbit Wars

🛰️

What it is

Kaggle competition centered on orbital simulation / strategy. Submissions are algorithmic strategies, not live agents.

🚫

Why it's not really agent engineering

You're not allowed to submit AI agents. AI is only used at authoring time — to help write the algorithms and strategies that get submitted.

🧠

Where AI fits

Use models to brainstorm strategies, write/refine the simulation code, and analyze opponent behavior — but the runtime is plain code.

🎓

Course relevance

Limited as a teaching artifact for agent engineering specifically. Better positioned as an "AI-assisted programming" example.

Local Hosting

Models on My Machine

💻

Quick spin-up

Briefly tried running a couple of local models via Ollama on my dev machine. Goal was to get a feel for latency, footprint, and quality at home before throwing them at a benchmark.

Why try it

No API costs, full control, offline-capable, useful for red-teaming / sensitive eval data.

What worked

Small models load fast and answer fine for narrow classification tasks.

Where it goes next

Feed local models into PromptFoo (next slide) for a real comparison.

Evaluation

PromptFoo

Open-source eval framework — three pillars in one tool.

📝

Prompt eval

Compare prompt variants on a fixed model with the same dataset and graders.

⚖️

Model eval

Hold the prompt fixed, vary the model — apples-to-apples quality / latency / cost.

🔥

Red teaming

Adversarial probes for jailbreaks, prompt injection, PII leakage, harmful output.

What I used it for

Spam / phishing email classification across several local Ollama models. Edit OLLAMA_MODELS in generate_config.py → write promptfoo.yaml → promptfoo eval. Lives under ollama/ and is independent of Agent_Frameworks/.

CTF

Agentic Gandalf

Used the gandalf-ctf skill to drive Claude Code through Lakera's prompt-security CTF. Each level guards a secret password under increasingly aggressive defenses.

🧙‍♂️ → 🔓

7 / 8 levels cleared

Claude Code, given the skill, beat seven of the eight Gandalf challenges autonomously — chaining prompt-injection strategies and adapting to defender responses without user intervention.

Why it's interesting

It's a clean test of whether a skill-equipped agent can autonomously attack a defender it's never seen before.

What broke down

Final level uses layered defenses (input filter + output filter + LLM judge). One-shot strategies stop working.

Course angle

Pairs with the PromptFoo red-teaming pillar — same threat model, opposite side of the table.
